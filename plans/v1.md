# omavita v1: a private health record for Omarchy

Plan, 2026-09-16. Status: draft for review. Written by Claude for Matthias Debernardini, after a 22-agent research sweep, a three-architect design panel and two fresh-context reviews.

## The product in one paragraph

omavita is a local health record for Omarchy (DHH's Arch plus Hyprland Linux). One tap in the iPhone share sheet sends a photo to the Linux box. Claude Code reads it through an MCP (Model Context Protocol, the tool interface Claude Code speaks) server, writes an analysis, and the analysis appears next to the photo in a native window built on gpui-kit. The same window charts the Apple Health data the phone already pushes and holds lab PDFs. Nothing leaves the machine except what the user asks Claude to read, and every such read is logged and shown.

First user: Matthias. The Intel MacBook Pro gets Omarchy via the free-space ISO install and becomes the box. The M5 Max MacBook stays the dev machine.

## Why this and not something that exists

The research found no Linux-native personal health record, no health MCP server that handles photos, no MCP server that stores results, and zero health plugins among 3,283 on the Omarchy marketplace. Anthropic's Apple Health connector is claude.ai and iOS only, not Claude Code. Fasten OnPrem is archived and OpenHealth is stale. OpenMed (openmed.life) is a Python clinical NER and de-identification library, not an app. The loop "photo lands, agent analyzes, result stored, GUI shows it" does not exist anywhere.

## What v1 does

- Photo and PDF intake from the iPhone share sheet over plain HTTP with a bearer token. Originals kept. A 1568 px EXIF-free JPEG rendition per photo, derived once.
- An MCP server with four tools: `sql_query` (read-only), `get_photo` (vision), `save_analysis` (write), `annotate` (label a photo).
- A gpui-kit window with five screens: Photos, Photo detail, Trends, Documents, Setup. Themed from Omarchy's `colors.toml`.
- Apple Health metrics from the Health Auto Export app, posted to the same daemon, charted as daily series with gaps visible.
- History backfill from Apple's `export.zip`, using the converter that already exists in agstaff.
- One-click install: an AUR package plus one setup command, and a clean uninstall. A plain `backup` command.

## What v1 does not do

- Nutrition, meals, calories. That stays in TraceHealth on the phone. Matthias said later, not now.
- Unattended daily vitals. Apple encrypts HealthKit while the phone is locked, so nothing can sync unless the phone is unlocked at that moment. Pushes are best effort with a lookback.
- Local vision models, OpenMed redaction, bundled literature MCPs. BioMCP (a keyless single-binary Rust server for PubMed, ClinicalTrials.gov and openFDA) is documented as an opt-in.
- SQLCipher or per-file encryption. LUKS is the at-rest layer. Setup shows red if the disk is not encrypted.
- The Omarchy bar-widget plugin, the Omarchy package repo entry, the Mac mini M1 build, QR pairing, Taildrop or LocalSend receivers, workouts and GPS routes, photo comparison sliders, a body map. Later layers.

## Architecture

One Cargo package at `~/Projects/omavita`: a library that never links gpui, and three binaries.

| Binary | Runtime | Job |
|---|---|---|
| `omavitad` | tokio + axum | Always-on intake listener on port 47831. Only writer for inbound data. |
| `omavita-mcp` | rmcp 3.4, stdio | Spawned by Claude Code per session. Reads, writes analyses and labels. |
| `omavita` | gpui-kit 0.6.1 on smol | The window. Subcommands `setup`, `uninstall`, `import`, `backup`, `doctor` run with no window. `probe` opens one frame and reports the GPU. |

Three processes because of two verified facts: gpui runs on smol, not tokio, so the listener cannot live in the GUI; and Claude Code spawns the MCP server as a short-lived child, so it cannot be the listener either. The daemon is a systemd user unit (`WantedBy=graphical-session.target`), the same way Omarchy runs its own Taildrop receiver. Photos land while the window is closed. No `o.launch_on_start` line in `autostart.lua`: Omarchy documents unit plus autostart as a double-start bug.

Pinned crates: `gpui-kit = "=0.6.1"`, `gpui-omarchy = "=0.1.2"` (reads Omarchy's theme and follows changes), `rmcp 3.4`, `rusqlite 0.40` (bundled SQLite, sync, one API for all three binaries), `axum` + `tokio`, `image 0.25`, `kamadak-exif 0.6`, `libheif-rs 3.0` behind `cfg(target_os = "linux")` against Arch's `libheif`, `pdf-extract 0.12`, `quick-xml 0.42` + `zip`, `sha2`, `serde`, `toml`, `chrono`. On macOS the HEIC rendition comes from `sips -s format jpeg`, which ships with the OS, so the whole loop runs on the dev machine before the box exists.

The `gpui-pre-*` crates under gpui-kit are Longbridge's weekly snapshot of Zed's gpui, published because Zed's own crate stalled. Licensing is clean (Apache-2.0). Zed has promised its own pipeline by end of September 2026. Pin exactly, budget one retarget later.

Data lives in `~/.local/share/omavita/`:

```
db.sqlite                  one database, WAL mode
photos/<sha256>.<ext>      original bytes, never modified
photos/<sha256>.view.jpg   1568 px long edge, orientation applied, no EXIF
docs/<sha256>.pdf          original document
```

Config and the bearer token live in `~/.config/omavita/config.toml`, mode 0600.

SQLite rules:

- Every process opens through one library function: `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, then migrate under `BEGIN IMMEDIATE` keyed on `PRAGMA user_version`. Any process can start first, and the GUI runs on the dev box with no daemon. A binary that finds a `user_version` newer than it knows refuses to open and says so.
- Busy timeout: 5 s in the daemon and MCP, 250 ms in the GUI. The GUI retries on its next poll tick instead of freezing.
- The MCP binary holds two connections: one read-only for `sql_query`, one read-write for events, analyses and labels.
- The GUI polls `PRAGMA data_version` once a second while visible and re-queries on change. Default auto-checkpoint handles the WAL. No sockets.
- After `pacman -Syu` replaces the binaries, the running daemon would keep the old code. It polls `/proc/self/exe` every few seconds and exits 0 when the link reads ` (deleted)`; `Restart=always` brings up the new binary. `doctor` compares the unit's start time with the binary's mtime and says "restart needed".

## Data model

```sql
photo     id, sha256 UNIQUE, ext, width, height, taken_at, taken_at_source (exif|field|receipt),
          received_at, source (shortcut|import), body_site, laterality, note
document  id, sha256 UNIQUE, received_at, title, pages, text, source
document_fts  FTS5 external-content index over document.text
analysis  id, photo_id NULL -> photo ON DELETE CASCADE, document_id NULL -> document,
          created_at, title, markdown, data JSON, model, content_hash UNIQUE
metric    name, day, qty, units, source, extra JSON, PRIMARY KEY (name, day)
events    id, at, actor (daemon|gui|mcp), kind, subject, detail JSON
```

- `metric` has one row per metric and local calendar day. `day` is a plain `YYYY-MM-DD` computed by one library function from either source's timestamp. `source` is provenance, not part of the key. The old Grafana pipeline keyed on timestamp and source and double-counted recent weeks where the phone's push and the `export.zip` backfill overlapped; this key makes that impossible. Last writer wins on `INSERT OR REPLACE`. Min, average, max, sleep stages and blood pressure pairs go in `extra`. Slugs match the ones the Grafana dashboard already uses: `weight_body_mass`, `resting_heart_rate`, `heart_rate_variability`, `step_count`, `sleep_analysis`, `vo2_max`, `walking_speed` and the rest.
- `body_site` is a fixed vocabulary listed in the MCP instructions (side plus region, lowercase), and `annotate` normalizes to it. Free text would break "earlier photos of this spot".
- `analysis` with both foreign keys NULL is a trend note about a metric. `content_hash` makes a retried `save_analysis` a no-op.
- `events` is the privacy ledger and the intake log in one table. The daemon logs accepted and rejected requests with the remote address. Every MCP call logs a row: `get_photo` records the pixel size sent, `sql_query` records the tables touched and the row count. Every row carries the Claude auth mode: `api-key` when the child's environment has one, else the login email from `~/.claude.json`, else `unknown`.

## MCP surface

Registered once with `claude mcp add --scope user omavita -- /usr/bin/omavita-mcp`, so `claude` works from any directory. The server's `instructions` field carries the workflow, the body-site vocabulary and the analysis record shape. No CLAUDE.md or skill file to find or maintain.

| Tool | Does | Returns |
|---|---|---|
| `sql_query(sql)` | Any SELECT. Read-only connection with `query_only=1`, rejected unless `Statement::readonly()`, 500-row cap, 5 s progress-handler abort. The description embeds the live schema from `sqlite_master` and notes that empty `document.text` means a scan. | Text block: columns and rows as JSON. |
| `get_photo(id)` | Reads `view.jpg`, base64-encodes it, logs the event. | One `image/jpeg` block plus one text block: id, taken_at, body_site, laterality, note, prior analysis ids for the same site. No `structuredContent`, no `outputSchema`. |
| `save_analysis(photo_id | document_id | null, title, markdown, data, model)` | Stores the assistant's write-up. | `{id, created_at}` |
| `annotate(photo_id, body_site?, laterality?, note_append?)` | Labels the photo the agent analyzed. | `{ok}` |

Why `get_photo` is shaped this way, verified by reading the Claude Code 2.1.273 binary: an MCP image block reaches the model as vision. Claude Code's pre-check counts one image as a flat 1,600 tokens, so a photo never trips the 25,000-token MCP output cap. The one way to trip it is base64 leaking into `structuredContent`, which Claude Code turns into a text block. MIME must be `image/jpeg`, `image/png`, `image/gif` or `image/webp`; HEIC would be written to disk with a placeholder. The real vision cost of a 1568 px rendition is 1,300 to 3,100 tokens depending on aspect ratio.

The instructions fix the order of work for a new photo: infer the body site from the image, `sql_query` for earlier photos with that site, `get_photo` the most recent prior, then `save_analysis` with the prior id in `data`, then `annotate`. The record shape: body site and laterality, lighting and scale note, plain-language description (size, shape, border, colours, surface, symmetry, surrounding skin), features stated as observations, change versus the prior photo, a differential list labelled as the assistant's output, red flags each marked present, absent or unknown, what to track and at what interval, a "consider a clinician" line, confidence and image-quality caveats. Markdown for the GUI, the same fields as JSON in `data`.

## Phone to box

**One endpoint.** `POST /upload` takes one multipart file part, sniffs the bytes (HEIC `ftyp`, JPEG, PNG, PDF magic), and routes to photo or document. The filename is never trusted. A sha256 hit returns the existing id with `duplicate: true`.

**The Shortcut**, named "Send to omavita": Receive Images and Files from Share Sheet; Repeat with Each; Get Contents of URL, POST `http://<box>:47831/upload`, header `Authorization: Bearer <token>`, Request Body Form, one File field `file` = Repeat Item, one text field `taken` = Date Taken as ISO 8601; End Repeat; Show Notification with the count. No Convert Image or Resize step, those strip metadata. First run: tap Always Allow. Apple's own action text confirms Form body means multipart. One 2026 project uses this exact recipe on plain HTTP; four others each confirm one element (Form body, plain `http://` to a LAN or Tailscale address, HEIC arriving). No one has published a captured request proving EXIF survives, so one device test is the exit gate for milestone 1.

**Photo ingest.** Write the original, decode. HEIC: libheif applies the container's own rotation during decode, so the EXIF orientation is not applied again. JPEG: apply EXIF orientation. Resize to 1568 px long edge, quality 85, no EXIF. Read `DateTimeOriginal` for `taken_at`, then the `taken` field, then receipt time, recording which. Insert, `notify-send`, reply in well under a second. Shortcuts has an unpublished ceiling near 60 seconds and dies when the screen locks.

**PDF ingest.** Write the original, run `pdf-extract` in a blocking task with the panic caught (it panics on malformed files), store the text or an empty string with a "no extractable text" badge for scans.

**Metrics.** Matthias already pays for Health Auto Export and runs an hourly REST automation to a Tailscale box. He adds a second automation with the same JSON envelope pointed at `http://<box>:47831/api/data`, header `api-key: <token>`, daily aggregation. Period: Previous 7 Days if the app offers it on a recurring automation, so a run that failed on a locked phone is repaired by the next one; the research confirms Since Last Sync and custom headers but not a 7-day period, so this gets checked in the app before milestone 3. Fallback: Since Last Sync plus a monthly `export.zip` import. The Node, Mongo and Grafana stack keeps running until Trends shows what he looks at. History comes from `export.zip`, not from Mongo.

**Firewall.** Omarchy Quattro enables ufw with default deny and opens only port 53317 (LocalSend). A POST to 47831 is dropped on a fresh install. Setup follows Omarchy's own Sunshine installer: `sudo ufw allow in proto tcp from 10.0.0.0/8 to any port 47831 comment omavita`, the same for `172.16.0.0/12` and `192.168.0.0/16`, then `sudo ufw reload`. Never Anywhere, never IPv6, never a pacman post-install hook. Over Tailscale no rule is needed: tailscaled's default netfilter mode accepts `tailscale0` traffic ahead of ufw. The daemon also refuses peers outside loopback, RFC1918 and `100.64.0.0/10`. The token is the real boundary; ufw is not one over the tailnet. `setup --no-firewall` exists for Tailscale-only boxes.

**Pairing address.** Tailscale MagicDNS name when tailscaled is up, else `<hostname>.local`, else the LAN IP. A bare IP changes with DHCP and the Shortcut's Always Allow grant is per host.

**When the box is off.** The phone shows the error and the user shares again later. Taildrop drops files into `~/Downloads` on Omarchy automatically, and the GUI has an Import button using the portal file dialog, so there is always a manual path.

LocalSend on the already-open port 53317 was rejected: it inherits Omarchy's allow-from-anywhere IPv6 rule, collides with the LocalSend app, and needs a self-signed HTTPS implementation of protocol 2.2.

## The Claude loop, step by step

1. Photo lands. Matthias shares a foot photo, taps "Send to omavita", sees "1 saved" on the phone and a desktop notification on the box.
2. He runs `claude` in any terminal: "Look at my newest foot photo in omavita, describe what you see, compare with earlier photos of the same spot, and save the analysis."
3. Claude Code spawns `omavita-mcp`. The model calls `sql_query` for the newest photos, `get_photo(12)`, infers "right foot, dorsal", queries earlier photos with that site, `get_photo` on the most recent prior, writes the record, calls `save_analysis` with the prior id, then `annotate(12, body_site="right foot, dorsal")`.
4. Stored. One `analysis` row and one `events` row per tool call, each with what was sent and under which Claude account.
5. The GUI's one-second poll sees the commit. The grid drops the "no analysis" badge. Photo detail shows the rendition, the metadata, "Shared with Claude today 14:03 (login matthias@...)", and the analysis as Markdown under the fixed line "Assistant output, written by your AI assistant at your request. This app does not diagnose."

## GUI screens

- **Photos.** Grid of renditions newest first, badge for photos without an analysis, filter by body site, Import button, the Miiskin-style sentence at the bottom. Sidebar navigation. No title-bar buttons: Hyprland answers every decoration request with server-side, gpui-kit then draws no controls, and Omarchy users close with SUPER+W. Tiled by default; the README documents an optional float rule for `hyprland.lua`.
- **Photo detail.** Full rendition, taken and received times with their sources, editable body site, laterality and note, the "shared with Claude" line, analyses as Markdown with model and date, "earlier photos of this spot" strip, Delete (cascades, removes files).
- **Trends.** Metric picker, 30, 90 and 365 day ranges, gpui-kit line chart with gaps left empty, stat tiles for latest value and 30-day baseline, trend notes below.
- **Documents.** List, detail with extracted text or the scan badge, search over FTS5, Open (copies to `$XDG_RUNTIME_DIR` and `xdg-open`s it; gpui has no PDF viewer).
- **Setup.** Daemon active and not stale, firewall rules as recorded by setup with their date (ufw state is root-only; `sudo -n ufw status` is tried and "unknown" shown if it fails), MCP entry present in `~/.claude.json`, disk encrypted (`lsblk -sno TYPE $(findmnt -no SOURCE /)` contains `crypt`), last accepted and last rejected upload, pairing card with address and token and Copy buttons, the Shortcut recipe, the Health Auto Export settings, a button that opens a floating terminal running `omavita-setup` when anything is red, and the retention note.

The app's own strings describe features, trends and baselines. They never name a disease or a threshold. That keeps the app on the general-wellness side of the FDA's 2026 guidance if it is ever shared. The differential list is Claude's, labelled as such.

## Install and remove

What the user does: Super+Space, Install, AUR, `omavita-bin` (or `omarchy pkg aur add omavita-bin`). Launch omavita. Setup shows one button, which opens a floating terminal running `omavita-setup`. Two password prompts in total, one for pacman and one for the firewall rules, unless Omarchy's passwordless-sudo window is on. Everything turns green and the pairing card appears.

What the package installs, as root via pacman: the three binaries in `/usr/bin`, `/usr/bin/omavita-setup` (a three-line shell wrapper carrying the `# omarchy:requires-sudo=true` header Omarchy's menus grep for, which execs `omavita setup`), `/usr/lib/systemd/user/omavitad.service` (`Type=simple`, `Restart=always`, `RestartSec=5`, `After=` and `PartOf=graphical-session.target`, `WantedBy=graphical-session.target`), `omavita.desktop` with `StartupWMClass=omavita`, an icon. `depends` is trimmed by `ldd` on the release binary: `libheif vulkan-icd-loader fontconfig wayland libxkbcommon-x11 libxcb zstd hicolor-icon-theme`. No `vulkan-driver` virtual dependency: with `--noconfirm` pacman takes the first provider and can pull `nvidia-utils` onto an Intel box, and Omarchy already installed the right driver on every supported install since 3.4.0 and on every upgrade via migration.

What `omavita setup` does, as the user, re-runnable, continuing past any failed step and reporting at the end: generate the token if absent, create the data directories, `systemctl --user daemon-reload && enable --now omavitad`, `claude mcp remove --scope user omavita` if present then `claude mcp add --scope user omavita -- /usr/bin/omavita-mcp` (the add is not idempotent on its own), the three ufw rules and reload, record the rules and the date in `config.toml`, print address, token and the Shortcut recipe. On a fresh Omarchy `claude` is a mise stub that downloads Claude Code on first call, so setup says "installing Claude Code, first use" before that step. This split is Omarchy's own pattern: pacman installs Zed, then `omazed setup` runs as the user.

`omavita uninstall`: disable the unit, `claude mcp remove --scope user omavita`, delete the three tagged ufw rules, keep the data unless `--purge`. Then `omarchy pkg drop omavita-bin`.

`omavita backup <dir>`: `VACUUM INTO` the database, then copy `photos/` and `docs/` by name (files never change, so the copy is incremental). The box is an old laptop with an aging battery; a v1 with no way to get data off it is not acceptable. Encryption of the backup is a later layer.

Release binaries are built in an `archlinux` container in GitHub Actions so glibc and the libheif soname match the target. The x86_64 tarball is what the PKGBUILD fetches.

## Privacy model

- Everything is local, in `~/.local/share/omavita`, on LUKS. LUKS is the default on both x86 ISO paths (full-disk and free-space); on omarchy-mac it is a Y/n prompt with a documented opt-out, so Setup checks and says so.
- Everything the model reads through the MCP goes to Anthropic: photo renditions, metric rows, analysis text, document text. Each read is an `events` row with what was sent and under which account, shown on the photo or document.
- GPS and all EXIF are absent from renditions. Originals keep their EXIF on disk.
- The listener has a 32-byte random bearer token, a scoped ufw rule, and a peer check. No TLS: Shortcuts cannot skip certificate checks, and Tailscale is WireGuard end to end already.
- No telemetry, no accounts, no cloud health APIs. Tailscale is optional and already on the phone.
- `sql_query` is read-only at the connection, the pragma and the statement.
- Retention of what was sent depends on the Claude account on the box. An API key means 30-day retention and no training. A Pro or Max login means the training toggle decides. Setup says so, for text as well as images.

## Milestones and their checks

Each milestone leaves one runnable check in `checks/`. Every headless check uses `claude -p --verbose --output-format stream-json --allowedTools <tools>`: `--verbose` is required with `stream-json`, and headless mode denies MCP tools not on the list. `docs/checks.md` records the Claude Code version each check last passed on.

**M0. The box and a hello window.** Human-gated: Omarchy Quattro on the Intel MacBook Pro via the free-space ISO install, LUKS left on. Repo scaffolded with `/rust-new`, crates pinned. `omavita probe` opens one frame under Hyprland, prints gpui's `GpuSpecs` (device name, driver, software-emulated flag) and `window_decorations()`, then exits.
Check: `omavita probe` prints a device name that is not `llvmpipe`, `software_emulated=false` and `decorations=Server`, and exits 0, tiled and floating. Anything else stops layout work until understood.
Until the box exists, everything else builds and runs on macOS, HEIC included via `sips`. try-omarchy on the Mac ships `vulkan-swrast` and is a smoke test, not a target.

**M1. The walking skeleton.** Library (`db`, `media`, `config`), `omavitad` with `POST /upload` and `GET /health`, `omavita-mcp` with all four tools and two connections, GUI with Photos and Photo detail, `data_version` polling. Run from the repo, MCP registered by hand.
Check, `checks/m1-loop.sh`:
1. Post `checks/fixtures/foot-portrait.heic` and a second foot photo to `127.0.0.1:47831`. Assert the first rendition is taller than wide.
2. Run `claude -p --verbose --output-format stream-json --allowedTools mcp__omavita__sql_query,mcp__omavita__get_photo,mcp__omavita__save_analysis,mcp__omavita__annotate 'Use omavita: analyze the newest photo, compare with the earlier one of the same site, save the analysis'`.
3. Assert `rg -c '"type":"image"'` is at least 1 and `rg -c 'OUTPUT TRUNCATED'` is 0.
4. Assert the second photo's analysis `data` names the first photo's id, and one `get_photo` event exists per photo.
Exit gate: one real share from the iPhone lands with `ext=heic` and `taken_at_source=exif`. This settles the one part of the phone path no source verified.

**M2. One-click install.** PKGBUILD, desktop file, icon, unit, the wrapper script, the archlinux-container release workflow, `setup`, `uninstall`, `backup`, `doctor` (headless, exit 1 on any red line), the Setup screen, AUR publish.
Check, from a clean state on the box:
1. `omarchy pkg aur add omavita-bin && omavita-setup && omavita doctor` exits 0.
2. `sudo ufw status | rg -c omavita` prints 3, and `~/.claude.json` has `omavita` under `mcpServers`.
3. `omavita backup /tmp/b` copies every photo file.
4. `omavita uninstall && omarchy pkg drop omavita-bin` leaves no unit, no rule, no MCP entry.

**M3. Metrics and Trends.** `POST /api/data` parsing the Health Auto Export envelope into daily upserts (about 150 lines), the Trends screen, the second automation on the phone with its period setting verified in the app.
Check, `checks/m3-hae.sh`:
1. Generate a 7-day fixture ending today and post it twice.
2. Assert the metric row count equals the fixture's distinct (name, day) count after both posts.
3. Run the headless `sql_query` check for that date range and assert 7 rows in the tool result.

**M4. History.** `omavita import <export.zip>`: port of `agstaff/crates/aghealth/src/commands/import_xml.rs`, minus the agcli wrapper, emitting `day` through the shared function and feeding the same upsert in-process. Years of data in Trends.
Check: post the M3 fixture, then import `checks/fixtures/export-small.zip` twice, where the fixture overlaps the same days; assert one row per (name, day) across the overlap, the weight on a known day equals the fixture, and the second import changes nothing.

**M5. Documents.** PDF routing in `/upload`, the GUI Import button, `pdf-extract` into `document` and `document_fts`, the Documents screen. The `sql_query` schema text updates itself.
Check: upload `checks/fixtures/lab.pdf` and `checks/fixtures/scan.pdf`; `SELECT count(*) FROM document_fts WHERE document_fts MATCH 'hemoglobin'` is 1; the scan row has empty text and the badge; the headless `sql_query` check can quote a line from the lab report.

Effort: about 11 to 13 agent-days of implementation with second-pass reviews, 2 to 3 calendar weeks. The two unknowns are front-loaded: gpui-kit on Hyprland (M0) and the real-phone HEIC test (end of M1).

## Decisions and what they rejected

| Decision | Rejected | Because |
|---|---|---|
| Three processes | Listener in the GUI or in the MCP binary | gpui is on smol; the MCP child is short-lived; photos must land with the window closed. |
| One package, three `[[bin]]`, gpui-free library | A four-crate workspace | Fewest crates that keep gpui out of the daemon and MCP binaries. |
| Share-sheet Shortcut to plain HTTP on 47831 | LocalSend on 53317; Taildrop watcher | Zero phone software beyond what he runs; LocalSend inherits the anywhere rule and needs HTTPS; Taildrop is alpha and account-gated. |
| One `/upload` endpoint that sniffs bytes | Separate photo and document endpoints and shortcuts | One Shortcut, one code path, PDFs from the phone for free. |
| Four MCP tools with a read-only SQL tool | Bespoke list and query tools | Claude writes SQL well when the schema is in the description; only bytes and writes get purpose-built tools. |
| Rendition derived once at ingest | Decode and resize at call time | The GUI cannot show HEIC either; the MCP tool stays a file read. |
| Metric key (name, day), source as provenance | (name, timestamp, source) like the Mongo pipeline | That key double-counted overlapping days in Grafana. |
| Health Auto Export as the metrics transport | A Find Health Samples shortcut; a HealthKit companion app | He already runs it; every path hits the locked-phone wall. |
| Photos as files, LUKS at rest, no SQLCipher | BLOBs in a SQLCipher database with a passphrase | Both target installs default to LUKS; key handoff to the MCP child is a layer the loop does not need. |
| rusqlite everywhere | sqlx | The GUI has no tokio; queries are milliseconds. |
| Instructions in the MCP server | A CLAUDE.md and skills in a `~/Health` folder | Works from any directory; one place to maintain. |
| `PRAGMA data_version` polling | A Unix socket from daemon to GUI | SQLite's documented cross-process change signal; no protocol. |
| No consent gate in `get_photo` | Refuse until the user confirms per photo | The user typed the request; the record is what matters. |
| No vulkan-driver dependency | `depends=(vulkan-driver)` | `--noconfirm` picks the first provider. |
| archlinux container for release builds | ubuntu runners | glibc and libheif soname must match the box. |
| Daemon exits when its binary is replaced | A pacman hook restarting the user unit | Root hooks cannot reach the session's user units; the unit's own restart can. |

## Risks

| Risk | Mitigation |
|---|---|
| Nobody has run gpui-kit 0.6.1 on Hyprland; chrome and rendering are read from source, not observed. | M0 is the gate. `probe` logs GPU and decorations. The `WAYLAND_DISPLAY=` X11 escape is documented, not designed for. |
| HEIC original with EXIF via the Form upload is plausible, unverified. | Sniff bytes, accept JPEG, fall back to the `taken` field and receipt time; the device test closes M1. |
| Health Auto Export may not offer a 7-day period on a recurring automation. | Checked in the app before M3; fallback is Since Last Sync plus a monthly `export.zip` import. |
| `gpui-pre` is one maintainer's mirror of Zed. | Exact pins; one retarget budgeted; no code touches gpui internals beyond gpui-kit's API. |
